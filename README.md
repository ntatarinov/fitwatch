# FitWatch — прототип

Локальный прототип приложения для тренировок: видео упражнений, план по дням, баллы и серия, ежедневный отзыв, профиль по правилам, дневник питания (с подсказкой по фото), стретчинг, тренер-диалог по дереву решений.

**Запуск:** `./serve.sh`, затем http://localhost:8080 (нужен интернет для видео YouTube; на телефоне в той же сети — http://<адрес-компьютера>:8080).

**Показ заказчику:** Профиль → «Загрузить демо» заполнит две недели данных, и сразу видны профиль, советы и серия.

## Версия 0.4: сервер, аккаунты, рейтинг (шаг 2A)
По просьбе Айдархана (переписка 31.10): база, данные пользователя (вес и рост) с бонусами и рейтингом. Тренеры и подписки идут следующими шагами.

- **Что работает:** регистрация и вход (пароли scrypt, сессии в cookie `HttpOnly`, ограничение попыток), вес и рост с историей и графиком, очки и бонус за серию на сервере (20 очков, растяжка 10; +5 с третьей тренировки подряд, +10 с седьмой; одна тренировка в день), рейтинг за неделю, месяц и всё время (только для тех, кто включил участие), перенос истории из браузера при регистрации, удаление аккаунта со всеми данными.
- **Как устроено:** одна серверная функция `api/index.js` (адреса /api/* направляет `vercel.json`) (на бесплатном тарифе их не больше 12), правила в `api/_lib/app.js`, схема и миграции в `api/_lib/schema.js`, база Neon (Postgres). Без базы сайт работает как раньше, а страницы аккаунта показывают «сервер ещё подключается».
- **Как подключить базу (один раз):** Vercel → проект `fitwatch` → Storage → Create Database → Neon → Connect Project. Vercel сам добавит `DATABASE_URL`; секреты в код и в чат не нужны. Таблицы создаются при первом запросе.
- **Защита:** изменения только с заголовком `X-FW` и своим Origin; пароли и сессии в базе только в виде хэшей; в рейтинге видны только имя и очки и только по согласию; вес, рост и самочувствие видны только владельцу.
- **Ограничения:** почта не подтверждается; очки в рейтинге считаются только по тренировкам, записанным в аккаунте (при регистрации переносятся последние 30 дней); оплата не подключена. Данные о здоровье: до выхода к настоящим пользователям из Казахстана нужно проверить требование о хранении персональных данных на серверах в Казахстане.
- **Проверка:** `npm test` (70 тестов, сервер проверяется на настоящем Postgres в памяти, нужен `npm i --no-save @electric-sql/pglite`), `npm run test:ui` (интерфейс в имитации браузера и сквозная проверка с базой, нужен `npm i --no-save jsdom @electric-sql/pglite`).

## Версия 0.5: тренеры, переписка, тарифы, закрытые программы, сон (шаги 2B и 2C)
- **Тренеры:** заявка тренера, подтверждение администратором, запрос клиента (нужен тариф «Персональный тренер»), кабинет тренера, чат. Тренер видит данные клиента только по его согласию: цели и ограничения, результаты и замеры включаются отдельными переключателями и отзываются в любой момент. Тренер не ставит диагнозы и не назначает лечение, это написано в интерфейсе.
- **Тарифы:** бесплатный, «Премиум», «Персональный тренер». Оплата не подключена: тариф выдаётся промокодом (`#/tariffs`). Промокоды создаёт администратор (`#/admin`).
- **Закрытые программы:** 4 расширенные программы на 4–8 недель с ростом нагрузки по неделям. Содержимое хранится только на сервере (`api/_lib/programs.js`) и отдаётся по тарифу, у бесплатного пользователя его нет даже в ответе сервера. Это черновики, их должен проверить тренер.
- **Сон:** журнал сна; если сна меньше 6 часов, совет дня предлагает лёгкую тренировку (`#/sleep`).
- **Настройка администратора (один раз):** в Vercel (Settings → Environment Variables) добавить `ADMIN_TELEGRAM_IDS` (ваш Telegram ID, через запятую можно несколько) или `ADMIN_USER_IDS` (ID аккаунта, его видно в «Аккаунте»). `ADMIN_EMAILS` больше не даёт прав: почту никто не подтверждает, и незанятую почту администратора мог бы зарегистрировать кто угодно. После изменения переменных нужна новая выкладка.
- **Проверка:** `npm test` (80 тестов), `npm run test:ui` (три сквозных сценария: интерфейс → сервер → база). Нужно: `npm i --no-save jsdom @electric-sql/pglite`.

## Версия 0.6: вход через Telegram
- **Как работает:** кнопка «Войти через Telegram» (новая схема входа Telegram на OpenID). Библиотека Telegram открывает окно входа и отдаёт странице `id_token`; сервер проверяет его подпись открытыми ключами Telegram (JWKS), издателя, адресата (Client ID бота), срок (15 минут) и одноразовое значение nonce (`api/_lib/telegram.js`). Так украденный токен нельзя использовать повторно. Создаётся аккаунт без почты и пароля или выполняется вход в существующий. Вход по почте остаётся запасным; Telegram можно привязать к аккаунту с почтой, тогда оба способа открывают один аккаунт.
- **Секреты не нужны:** проверка идёт только по открытым ключам. Токен бота и Client Secret в Vercel и в код класть не нужно.
- **Настройка (один раз):** в Telegram `@BotFather` создать бота, открыть бота → **Login Widget** → в **Trusted Origins** добавить `https://fitwatch-six.vercel.app`, в **Redirect URIs** добавить `https://fitwatch-six.vercel.app/`. В Vercel (Settings → Environment Variables) добавить `TELEGRAM_CLIENT_ID` (число Client ID со страницы Login Widget, оно публичное). Для администратора по Telegram: `ADMIN_TELEGRAM_IDS` (числовой идентификатор; свой можно узнать у `@userinfobot`). Затем выложить заново.
- **Безопасность:** алгоритм подписи берётся только из разрешённого списка (RS256, ES256, EdDSA), `none` и подмена алгоритма отклоняются; попытки ограничены; удаление аккаунта без пароля требует слова УДАЛИТЬ.
- **Дальше:** бот сможет присылать напоминания и уведомления о сообщениях тренера (право писать запрашивается при входе); мини-приложение внутри Telegram.
- **Проверка:** `npm test` (80 тестов), `npm run test:ui` (четыре сценария). Настоящий вход через Telegram проверяется на живом сайте после настройки.

## Версия 0.9.7: 3D-нажатие на телефоне и авторство идей
- **Исправлено выбор мышцы в 3D.** Если повернуть модель на спину, нажатие выбирало грудь, а не мышцы спины. Причин две: (1) модель сжата в целые числа, а луч нажатия в Three.js r128 читал их «как есть», поэтому попадания были случайными; теперь вершины переводятся в дробные числа при загрузке; (2) слои мышц в модели лежат вплотную и луч доставал мышцы с другой стороны тела. Теперь со стороны груди не выбираются мышцы спины (трапеции, трицепс, широчайшие, поясница, ягодицы, задняя поверхность бедра), со стороны спины — грудь, пресс, бицепс и квадрицепс; из слоёв на одной глубине берётся мышца, центр которой ближе к точке нажатия. Проверено на самой модели: спереди выбираются грудь, пресс, бицепс, квадрицепс, икры, сзади — трапеции, поясница, ягодицы, задняя поверхность бедра. На настоящем телефоне не проверялось.
- **Авторство:** статистика тренировок — идея **Айдархана**, записана как «Добавлено позже» (N1) на странице «Идеи команды», в проценты его 11 пунктов не входит (список пересказывает оригинал); 3D-модель тела — идея **Сани** (A2).

## Версия 0.9.6: запись тренировок и статистика
- **Запись тренировки** (`#/log`): выбираешь упражнения, для каждого вносишь подходы, повторения и вес; идут часы. В конце видишь итог: сколько всего поднято (повторения × вес), число подходов, время. Можно начать с нуля, повторить прошлую тренировку или открыть день готовой программы или плана кнопкой «Записать подходы и веса»: упражнения подставятся. Незаконченная тренировка хранится как черновик.
- **Готовая программа без записи:** новичок по-прежнему просто отмечает программу сделанной. Это считается тренировкой дня, но веса и времени не даёт: их никто не измерял. Если за тот же день записана тренировка по этой программе, она не считается дважды.
- **Статистика** (`#/stats`): неделя / месяц / год / всё. Тренировок, время, поднятый вес; две фигуры (спереди и сзади), мышцы окрашены уровнем: Дерево (меньше 5 рабочих подходов в неделю), Бронза (5–9), Серебро (10–14), Золото (15 и больше). Уровни — ориентир, а не оценка. Столбики по неделям (вес и число тренировок) и нагрузка по мышцам.

## Версия 0.9: аудит и исправления
Аудит по трём направлениям (сервер и безопасность, логика страниц, интерфейс на телефоне); каждая найденная ошибка воспроизведена, исправлена и закрыта тестом (`test/audit.test.js`, `test-ui/audit-flow.js` и дополнения в остальных тестах).
- **Безопасность сервера.** Администратор только по подтверждённой личности (`ADMIN_TELEGRAM_IDS` или `ADMIN_USER_IDS`), `ADMIN_EMAILS` больше прав не даёт. Тренер, с которого сняли подтверждение, теряет доступ, его открытые связи закрываются. Код младшего тарифа не продлевает старший. Переписка и принятие запроса требуют действующей подписки клиента. Чужие неверные пароли не блокируют хозяина почты. Одноразовый код входа Telegram привязан к браузеру. Перенос истории из браузера — один раз, 14 дней, без бонусов. Неверный ввод даёт 400, а не 500. Заголовки: запрет встраивания сайта в чужие страницы, `nosniff`, `Referrer-Policy`.
- **Данные.** Показываются последние 400 замеров, после удаления замера в профиле последний оставшийся. Испорченное хранилище в браузере не ломает приложение. Тренировка без сети отправляется позже. Две вкладки не затирают данные друг друга. Вход в существующий аккаунт не переносит туда данные этого устройства (только регистрация).
- **Страницы.** Медленный ответ сервера не рисует страницу поверх той, куда ушёл человек. Чат: без двойной отправки, дублей и бесконечного опроса. Приветствие только гостю, когда сервер ответил; закрывается при входе. Удаление аккаунта — поле на странице вместо системного окна. Сервис-воркер хранит оболочку одной версии целиком, зависшая сеть ждёт до 4 секунд.
- **Интерфейс.** Поля не выталкивают кнопки за край на узком экране, касания от 40 px, подписи у полей, группы выбора с заголовками, читаемые закрытые достижения, тёмная тема без светлых остатков, строка состояния iPhone читается, отступы под вырез, правила баллов и серии написаны так, как считает сервер, единые «баллы» и обращение на «ты», метки идей команды только в Pro.

## Как устроено
- `data.js` — программы, упражнения, ответы тренера. Видео — id ролика YouTube.
- `catalog.js`, `planner.js`, `nutrition.js`, `body.js`, `pages.js` — каталог, подбор плана, питание с БЖУ, схема тела, новые страницы.
- `achievements.js`, `fx.js` — уровни и достижения; звуки, конфетти, уведомления.
- `engine.js` — движок профиля и советов (правила, без ИИ), чистые функции.
- `tree.js` — движок дерева диалога тренера; само дерево — `TRAINER_TREE` в `data.js`. Следующий вопрос и формулировки зависят от пройденного пути, варианты скрываются по состоянию пользователя, есть «Назад».
- `photo.js` — эксперимент «калории по фото»: модель MobileNet в браузере (загрузка с CDN, ~15 МБ при первом использовании), без сервера и API.
- `app.js` — страницы и действия, данные в localStorage браузера.
- `METHOD.md` — метод тренера, из которого выведены функции.

## Правила
- Основные баллы: +20 за «Тренировка сделана» (+10 за растяжку), одна тренировка в календарный день.
- +5 за просмотр видео: засчитывается при ≥ 80% проигранного (перемотка не считается).
- Серия: между тренировками не больше одного дня отдыха (разница дат до 2); два дня без тренировки подряд прерывают серию.
- Профиль считается с 3 отзывов за последние 14 дней.

## Тесты и ограничения
- Дерево проверяется на целостность (`Tree.validate`): нет битых ссылок, циклов и недостижимых узлов.
- Фото: модель знает общие продукты (фрукты, овощи, пицца, бургер), не знает плов, бешбармак, баурсаки и не определяет порцию — выбор вручную. Нужен интернет для первой загрузки модели.
- Калорийность казахских блюд в быстрых продуктах — ориентировочная, перед использованием сверить с диетологом.
- Данные хранятся только в браузере пользователя.
